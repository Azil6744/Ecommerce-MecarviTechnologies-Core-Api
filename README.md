# CMS Backend - Laravel API

A Laravel-based Content Management System (CMS) backend API with authentication, role-based access control, and queue processing capabilities.

## Features

- **Laravel Sanctum Authentication**: Secure API token-based authentication
- **Role-Based Access Control**: Three roles - Super Admin, Editor, and Viewer
- **Versioned API Routes**: All endpoints under `/api/v1/` prefix
- **PostgreSQL Database**: Primary database for production-ready applications
- **Laravel Queue with Redis**: Background job processing for emails, form submissions, logs, and cache warming
- **RESTful API**: Clean and well-documented API endpoints

## Requirements

- PHP >= 8.1
- Composer
- PostgreSQL >= 12.0
- Redis (for queue processing)
- Node.js & NPM (for frontend assets, if needed)

## Installation & Setup

### 1. Clone the Repository

```bash
git clone <repository-url>
cd cms_backend
```

### 2. Install Dependencies

```bash
composer install
```

### 3. Environment Configuration

Copy the `.env.example` file to `.env`:

```bash
cp .env.example .env
```

Generate the application key:

```bash
php artisan key:generate
```

### 4. Configure Environment Variables

Edit the `.env` file and update the following configuration:

```env
APP_NAME="CMS Backend"
APP_ENV=local
APP_KEY=base64:... (generated by key:generate)
APP_DEBUG=true
APP_URL=http://localhost

# Database Configuration (PostgreSQL)
DB_CONNECTION=pgsql
DB_HOST=127.0.0.1
DB_PORT=5432
DB_DATABASE=cms_backend
DB_USERNAME=postgres
DB_PASSWORD=your_password

# Redis Configuration (for queues)
REDIS_HOST=127.0.0.1
REDIS_PASSWORD=null
REDIS_PORT=6379
REDIS_DB=0

# Queue Configuration
QUEUE_CONNECTION=redis

# Mail Configuration (for notifications)
MAIL_MAILER=smtp
MAIL_HOST=mailhog
MAIL_PORT=1025
MAIL_USERNAME=null
MAIL_PASSWORD=null
MAIL_ENCRYPTION=null
MAIL_FROM_ADDRESS="noreply@example.com"
MAIL_FROM_NAME="${APP_NAME}"
```

### 5. Create PostgreSQL Database

Connect to PostgreSQL and create the database:

```bash
# Using psql
psql -U postgres
CREATE DATABASE cms_backend;
\q

# Or using createdb command
createdb -U postgres cms_backend
```

### 6. Run Database Migrations

```bash
php artisan migrate
```

This will create all necessary database tables including:
- `users` table with role support
- `personal_access_tokens` table for Sanctum authentication
- `password_reset_tokens` table
- `failed_jobs` table for queue job tracking

### 7. Seed Database

Seed the database with default admin user and roles:

```bash
php artisan db:seed
```

This creates:
- **Super Admin User**:
  - Email: `admin@gmail.com`
  - Password: `123456`
  - Role: `super_admin`
  
  **⚠️ Important**: Change the admin password immediately after first login!

### 8. Install and Configure Redis (for Queue Processing)

#### On macOS (using Homebrew):
```bash
brew install redis
brew services start redis
```

#### On Ubuntu/Debian:
```bash
sudo apt-get install redis-server
sudo systemctl start redis-server
sudo systemctl enable redis-server
```

#### On Windows:
Download and install Redis from: https://github.com/microsoftarchive/redis/releases

Or use Docker:
```bash
docker run -d -p 6379:6379 redis:alpine
```

### 9. Start Queue Worker

Start the Laravel queue worker to process background jobs:

```bash
php artisan queue:work redis --verbose
```

For production, use a process manager like Supervisor to keep the queue worker running.

### 10. Start Development Server

```bash
php artisan serve
```

The API will be available at `http://localhost:8000`

## API Endpoints

### Base URL
All API endpoints are prefixed with `/api/v1/`

### Authentication

#### Register User
**POST** `/api/v1/register`

Request Body:
```json
{
    "name": "John Doe",
    "email": "john@example.com",
    "password": "password123",
    "password_confirmation": "password123"
}
```

Response (201):
```json
{
    "success": true,
    "message": "User registered successfully",
    "data": {
        "user": {
            "id": 1,
            "name": "John Doe",
            "email": "john@example.com",
            "role": "viewer",
            "email_verified_at": null
        },
        "token": "1|xxxxxxxxxxxxx",
        "token_type": "Bearer"
    }
}
```

#### Get Authenticated User
**GET** `/api/v1/user`

Headers:
```
Authorization: Bearer {token}
```

Response (200):
```json
{
    "success": true,
    "data": {
        "user": {
            "id": 1,
            "name": "John Doe",
            "email": "john@example.com",
            "role": "viewer",
            "email_verified_at": null
        }
    }
}
```

#### Logout
**POST** `/api/v1/logout`

Headers:
```
Authorization: Bearer {token}
```

Response (200):
```json
{
    "success": true,
    "message": "Successfully logged out"
}
```

## User Roles

The system includes three user roles:

1. **Super Admin** (`super_admin`):
   - Full system access
   - Can manage users, roles, and all content
   - Can access admin panel

2. **Editor** (`editor`):
   - Can create and edit content
   - Cannot manage users or system settings
   - Can access admin panel with limited permissions

3. **Viewer** (`viewer`):
   - Read-only access
   - Default role for new registrations
   - Cannot access admin panel

## Database Structure

### Users Table
- `id`: Primary key
- `name`: User's full name
- `email`: Unique email address
- `email_verified_at`: Email verification timestamp
- `password`: Hashed password
- `role`: Enum (`super_admin`, `editor`, `viewer`)
- `remember_token`: Remember me token
- `created_at`: Creation timestamp
- `updated_at`: Update timestamp

## Queue Configuration

The application uses Redis for queue processing. Background jobs are processed for:
- Email notifications
- Form submissions
- Log processing
- Cache warming

### Running Queue Workers in Production

For production environments, use Supervisor to manage queue workers:

1. Install Supervisor
2. Create a supervisor configuration file
3. Start and enable the supervisor service

Example supervisor config (`/etc/supervisor/conf.d/laravel-worker.conf`):
```ini
[program:laravel-worker]
process_name=%(program_name)s_%(process_num)02d
command=php /path/to/artisan queue:work redis --sleep=3 --tries=3 --max-time=3600
autostart=true
autorestart=true
stopasgroup=true
killasgroup=true
user=www-data
numprocs=2
redirect_stderr=true
stdout_logfile=/path/to/storage/logs/worker.log
stopwaitsecs=3600
```

## Security Considerations

1. **Change Default Admin Password**: Immediately change the default admin password after first login
2. **Environment Variables**: Never commit `.env` file to version control
3. **API Tokens**: Store tokens securely and use HTTPS in production
4. **Rate Limiting**: Consider implementing rate limiting for API endpoints
5. **CORS**: Configure CORS properly for production environments

## Troubleshooting

### Database Connection Issues
- Verify PostgreSQL is running: `pg_isready`
- Check `.env` database credentials
- Ensure database exists: `psql -U postgres -l`

### Redis Connection Issues
- Verify Redis is running: `redis-cli ping`
- Check Redis port (default: 6379)
- Ensure Redis is accessible from your application

### Queue Not Processing
- Ensure queue worker is running: `php artisan queue:work`
- Check queue connection in `.env`: `QUEUE_CONNECTION=redis`
- View failed jobs: `php artisan queue:failed`
